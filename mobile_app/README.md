# 签到助手 Android 内测版

当前版本 0.6.5（内部测试版），Flutter Android，包名 `com.xmum.attendance_assistant`。可覆盖安装并保留本机账号。

## 使用

主页提醒签到时连接名为 Student 的 Wi-Fi，请勿使用 Student-5G。

账号菜单提供“查询校园网会话（不切换）”：使用学校在线设备接口读取该账号的在线 IP，同时显示当前手机 IP 和认证状态，便于区分当前设备、旧 IP 或其他设备的会话。只查询，不注销任何设备。注销阶段核验接口返回成功且当前 IP 连续两次确认离线才继续；单次离线结果不代表账号在所有设备上离线。登录出现 E2620 时自动查询会话列表并显示诊断；不会自动注销其他 IP。

注销方式按当前页面的 `MacAuth` 配置选择：启用时使用解绑接口，当前 IP 已离线也会发送解绑请求；未启用时使用普通注销接口。当前教学楼启用了 MacAuth。实测中学校曾拒绝账号的在线会话列表查询，客户端会显示查询返回码和脱敏原因，不能据此确认其全局会话已清除。

校园网认证参数从手机当前 Wi-Fi 下的学校登录页面读取：注销前读取一次，手动重连后再次读取，统一用于 `ac_id`、加密内容中的 `acid` 和登录校验值，并读取 `nas`。因此可适配宿舍的 `acid=1` 和本次教学楼的 `acid=2`，不把某个场所的值写死。页面参数缺失、格式不支持或页面 IP 与手机 Wi-Fi 不一致时停止，不回退到默认值。BAS 超时会明确提示接入点认证设备未响应。

增加或编辑账号可选填「AC系统密码」，对应 `https://ac.xmu.edu.my/index.php`，账号沿用 Campus ID。该密码独立加密保存，不会自动代用签到系统或校园网密码；编辑留空保持已存值。提供独立显示/隐藏开关，并随加密账号文件传输。旧账号和旧导出文件缺少此字段时默认为空；导入包含此字段的文件需使用 0.5.6 或更高版本。

## 自动课表与上课提醒

保存新账号或更改 AC系统密码后，应用自动创建独立 AC 会话、登录、核验 Student ID、读取当前学期 Course List，并将课程名称、星期、起止时间、地点及教学周保存到 Android 安全存储。密码未填时仍可保存账号和执行原签到流程；课表提示尚未获取。已有填写密码但尚无课表的账号会在启动后补充读取，已有缓存可直接显示，不等待网络。导入含 AC 密码的新账号也会获取课表。

首页账号卡片平时只显示姓名/备注和 Campus ID；课程时间内额外用绿色显示“正在上课”、课程名称及上课地点。每 30 秒及应用回到前台时刷新，多个同时上课的记录都显示，课程结束即恢复精简显示。卡片菜单提供“查看课表”和“刷新课表”，课表页按星期显示全部课程、更新时间及获取状态/错误。抓取失败保留旧课表，避免清空已存记录。删除账号时同时清理对应缓存。

时间判断固定为马来西亚 UTC+8，并核对该课程的 Teaching Week。当前内置 2026/09 本科校历：第一教学周从星期日 2026-09-27 起算，当前课程的有效周以页面返回的周列表为准。校历来源：[学校本科校历](https://www.xmu.edu.my/sites/default/files/2025-08/2026-Undergraduate-Academic-Calendar.jpg)。其他学期可以读取并保存课表，但教学周起点尚未核对时不显示“上课中”；非本科课程需要匹配其自身校历，当前提醒适用本科账号。

课表描述的是排课安排，不代表教师已经开放签到，也不能确认临时调课、停课或到场。签到流程仍查询学校实时签到状态。课表读取与签到请求串行处理，读取过程中暂不能开始签到，以免 Wi-Fi 绑定影响正在执行的请求；“查看课表”页面显示当前读取步骤。每次读取结束退出本轮 AC 会话并清除本地 Cookie，不修改校园网账号。课表缓存独立于加密账号档案；换手机导入账号后重新读取。

1. 首页点「增加账号」，填写姓名、Campus ID、签到系统密码和独立的校园网密码。已有账号在「编辑账号」中补填校园网密码；编辑留空保持原值。两种密码均由安全存储保存，并包含在加密导出文件里，旧账号文件仍可导入。
2. Attendance Code 可选：老师设置验证码时输入四位数字，否则留空并直接点击本人账号。应用按提交前最新课程签到方式处理：验证码签到要求四位数字；网络环境签到省略验证码，由学校服务器核验实际网络。验证码只在内存中保存；应用空闲进入后台时自动清空。账号编辑页两种密码都提供独立显示/隐藏开关。
3. 手机连接 Student 网络。学生本人在老师监督下点击自己的姓名，即确认本人到场声明。应用先固定请求到 Wi-Fi，查询当前认证账号、注销解绑并确认离线，随后打开完整 WLAN 设置。请在系统中忽略/删除 Student，再重新选择 Student 连接；出现“需要登录”后返回应用，不要在网页手动登录。应用检测新连接重新请求认证，且用户已返回应用后，再读取 IP、复核离线状态、获取新挑战值，使用校园网密码登录并核验在线账号，随后进入教务流程。缺少校园网密码、注销未完成、登录拒绝或身份不匹配均停止。应用只允许一个任务运行。
4. 唯一可签到课程自动继续；多个候选要求人工选择；零课程停止。提交前再次查询课程状态。
5. 只有提交接口返回布尔 `true` 且重新查询该课程显示 `attendanceStatus=1`，才显示签到成功。
6. 每个账号结束后尝试退出教务/CAS 会话，清空本地 Cookie、Token 和用户身份，解除应用的 Wi-Fi 路由绑定。校园网账号保持在线，下次流程开始时再注销切换。失败不自动重发签到请求。

主页账号区新增「加密导出」和「导入账号」：导出时设置至少 12 字符的传输密码，并通过系统文件选择器保存 `.xmumaccounts` 文件；把文件传到另一台 Android 手机后，在同一应用中选择文件、输入传输密码并预览新增及重复账号数量。可选择仅添加新账号，或更新相同 Campus ID 的账号；其他本机账号保留。文件采用 PBKDF2-HMAC-SHA256（310000 次）派生密钥与 AES-256-GCM 加密，账号姓名、Campus ID 和密码不会以明文写入文件。传输密码不保存在应用里，遗忘后不能恢复导出文件。

卡片右侧菜单提供编辑、删除（需确认）和「测试登录 / 查询（不签到）」。右上角可打开学校原页面独立核验；不会将应用的认证信息传给外部浏览器。点击账号后打开独立步骤页，显示正在进行的步骤、已完成记录和失败原因；结果会保留至用户返回列表。

## 已实现

- 多账号新增、编辑、唯一 Campus ID 检查、重复账号确认更新、删除确认、搜索，以及跨 Android 手机的加密批量导入导出。
- Android 安全存储（默认 AES-GCM 数据加密和 Keystore 保护的密钥）；禁用应用系统备份和明文 HTTP。安全存储读失败时不覆盖原数据；关闭插件自动清库选项。
- 业务状态机与 Provider 抽象分离，当前实现 HTTP/API Provider。
- CAS 网页同款 RSA 编码、CAS 票据交换、教务身份初始化、学期查询、课程查询、签到提交、结果再次核验。
- CAS 票据交换后若学校返回自身域名的 HTTP 回调，改用 HTTPS 请求该地址；其他目标继续拦截。
- 教务登录状态同步若返回普通服务器拒绝，步骤页标记警告并继续检查学期和课程读取；认证失效、网络故障及必要接口失败仍停止。
- 学校当前服务对业务 JSON POST 的旧表单 Content-Type 返回 HTTP 415，现使用 application/json；已用手机上保存的账号进行只读登录与课程查询验证。
- 马来西亚 UTC+8 课程时间判断，已签到、教师锁定、其他出勤状态、结束课程、缺少关键字段等停止。
- 网络环境签到（attendanceMethod=1）使用当前学生校园网会话，经同一提交接口签到，省略 quickResponse；由学校服务器核验网络环境。提交不自动重试。
- CAS 图形验证码、二次验证、绑定或改密要求均停止自动流程，不绕过学校校验。
- 内存运行记录只保留时间与结果类型；密码、签到码、Cookie、Token、CAS 票据不写日志。

## 验证与限制

- 已做静态分析、单元/界面/请求契约测试。CAS RSA 测试向量来自已下载的学校原始前端加密函数，仅使用虚构测试文本。
- 真机测试使用独立安全存储命名空间和离线 Provider，不写真实考勤记录。
- 已使用真实账号完成校园网切换、教务登录和课程查询；尚未提交真实签到，用户将在开放签到时段自行验证验证码与无验证码签到。不能把 mock 测试通过视为学校真实签到验收通过。
- 接口字段和登录响应依据 2026-10-05 前端脚本实现；学校变化或未观测到的返回结构会安全失败。请求成功不能代表学校确认出勤。
- 当前严格要求提交响应 data 为布尔 true；如果学校实际返回其他结构，需要在获得脱敏响应结构后更新 Provider，不能放宽为任意真值。
- 当前没有 Windows 发布包、WebView 自动操作、无人值守全班批量签到或后台定时签到。
- 本版使用同一台电脑的 Android debug 签名，适合当前内部联调；不是面向公开发布的正式签名包。保留原 debug keystore 才能继续覆盖安装。

## 源码

- `lib/main.dart`：主页与账号管理。
- `lib/flow_progress_page.dart`：独立步骤页、状态记录和错误展示。
- `lib/account_store.dart`：安全存储。
- `lib/portable_archive.dart` 与 Android `MainActivity.kt`：加密账号档案、系统文件选择器和导入合并。
- `lib/domain.dart`：课程规则、统一错误和签到状态机。
- `lib/api_provider.dart`：隔离 HTTP 会话、CAS、学校接口。
- `test/`：规则、接口契约、加密向量和界面测试。
- `integration_test/smoke_test.dart`：Android 安全存储和离线交互测试。
- 接口兼容性依据学校公开前端资源；本地分析资源不纳入公开仓库。

## 开发命令

```powershell
D:/DevTools/flutter/bin/flutter.bat analyze
D:/DevTools/flutter/bin/flutter.bat test
powershell -File scripts/test-device.ps1 -DeviceSerial <device-id>
D:/DevTools/flutter/bin/flutter.bat build apk --debug --flavor production
adb -s <device-id> install -r build/app/outputs/flutter-apk/app-production-debug.apk
```

在 `mobile_app` 目录执行。真机测试使用独立的 `.qa` 包名及 `--no-uninstall`；不要直接运行未带这两个参数的 `flutter test integration_test/...`，其默认卸载行为曾清空正式应用账号。对真实账号的测试优先使用卡片菜单里的只读测试，确认能登录及获取课程后，再在学校实际开放时由在场学生测试签到。

手动重连：打开完整 WLAN 设置，操作“忽略 Student → 重新连接”，最多等待 3 分钟。必须检测到旧连接消失、新连接曾进入 Android Captive Portal（需要认证）状态，并等待用户返回应用和连接稳定后才继续。仅出现新的 Network 或“已连接”不会通过；IP 可以保持原值。重连后仍核验学校当前 IP 已离线，避免用户在网页提前登录了别的账号。普通 Android 应用不能静默删除系统保存的 Wi-Fi 配置，因此保留手动系统操作，不依赖 Shizuku。是否进入认证状态由 Android 与学校网络实际探测决定，应用不能通过改提示文字强制学校要求登录。
